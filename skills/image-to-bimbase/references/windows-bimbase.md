# Windows BIMBase 环境配置

## 软件与路径

需要用户自行安装 BIMBase 2024、其嵌入式 Python/SDK（`pyp3d`）和 VS Code，并准备有权使用的组件库。本项目不分发这些软件、组件或历史工程。

在当前 PowerShell 会话设置以下环境变量，值必须是本机真实绝对路径：

| 变量 | 用途 |
|---|---|
| `BIMBASE_COMPONENTS_DIR` | 道路/铁路 Python 组件库 |
| `BIMBASE_EXE` | BIMBase.exe |
| `BIMBASE_PYTHON` | SDK 配套嵌入式 python.exe |
| `VSCODE_EXE` | Code.exe |
| `BIMBASE_OUTPUT_ROOT` | 可选，成果根目录 |

首次执行先验证路径和 SDK 版本。未设置时可从已安装应用及用户指定目录发现；仍缺少关键依赖时再询问。PowerShell 可用 `WScript.Shell` 的 `CreateShortcut(path).TargetPath` 解析用户指定的快捷方式。不要把其他机器的安装位置当默认值。

以下 SDK 经验来自原工作流环境，需要结合实际安装版本验证。

## Python 与几何

- BIMBase SDK 使用嵌入式 Python 3.7；不要引入 `math.dist` 等较新版本 API。纯布局预处理可以另用系统 Python，保存 JSON 后交给 SDK。
- 在导入 `pyp3d` 之前处理脚本选项并执行 `sys.argv=sys.argv[:1]`。SDK 会把额外命令行参数当作宿主进程信息，曾导致连接挂起。
- PowerShell 设置 `$env:PYTHONIOENCODING='utf-8'`，使用 `-u -B` 便于查看进度。输出模型统一毫米，布局数据可以使用米，转换只在明确边界执行。
- 多个 BIMBase 窗口时必须识别目标宿主；过去 SDK 连接受当前前台进程影响。
- `get_entityid_by_activemodel()` 在本机曾正确取得当前场景实体；`get_all_entityid()` 曾返回空列表，即使模型可见。不要仅靠后者认定工程为空。
- 对大场景批量调用 `get_noumenon_on_entityid()` 曾触发异常或长时间无响应。优先保存分组生成清单，避免遍历回读全部实体来做例行核验。当前空白工程检查仍需结合窗口路径、可见场景和活动模型实体数。
- 组件代码可能在导入或构造时自动生成几何；检查顶层副作用，使用独立模块名称及按需延迟构造。复用加载器前阅读其实际实现。
- 直公路组件自身旋转与横向居中组合可能错位：优先在局部原点生成，再对整体进行旋转和平移。桥梁局部桥面高程须读取源码，不能把实例原点直接当桥面。
- 修改副本遇只读属性时，仅解除新交付副本的只读；不要修改组件库或旧交付权限。

## 界面与故障恢复

使用当前环境实际提供的窗口控制与截图工具，不依赖历史像素坐标。每次新建、另存、打开、保存前后都检查截图或控件及工程标题。不同窗口、缩放和输入法可能改变行为。中文 PowerShell 脚本在 Windows PowerShell 下使用 UTF-8 BOM。

外部脚本的 `clear_scene` 可能含工程硬编码路径，不作为通用清空工具。参数迭代始终按入口规则新建版本；生成中断需要重试时，优先另建空白尝试工程，保留本次失败现场和日志，不因重试删除旧交付或当前不明来源的几何。临时脚本和后台辅助程序不弹出无关窗口。

`set_view_direction_by_rotMatrix()` 后界面可能尚未刷新；可短暂等待后调用 `zoom_all_view()`，观察结果再调整。截实际 BIM 视口，避免把识别图当模型生成证据。

若窗口突然转到用户其他项目，停止发送会修改工程的输入，重新识别目标。一次失败先查进程、日志和保存文件；同一动作再次失败时改用已验证的替代方法，不持续重试同一故障接口。无安全恢复路径时保留已有成果，说明阻塞点；不无限重启程序或终止其他项目的进程。
