# 图片识别与 BIMBase 建模

## 开工与协作

使用中文。用户本次指令优先于本 skill 的默认设置。用户要求讨论或修改 skill 时，只修改 skill 并继续讨论，不启动建模。

每个新图片任务先查看图片，再集中提出**恰好 5 个相关问题**；等用户全部回答后才编写本次模型代码、操作建模软件和生成模型。优先询问影响结果且尚未明确的线路类型、范围、尺度、车道或轨道配置、上下层关系及遮挡段。已经确定的默认偏好和本次明确说明不机械重复询问，问题针对该图的具体细节。“由你决定”视为已回答；回答不完整时只补问缺项。同一任务的参数修改不重启一轮 5 问。

回答完后自动完成识别、编码、新建工程、生成、检查修正和保存，中途简要汇报实际进展和关键假设。识别图、初步模型不设额外确认关卡。仅遇无法合理判断的关键缺失信息、实际权限阻塞或超出已确认范围的操作时暂停相关步骤，说明原因，并继续不依赖该问题的工作。

“接管电脑”限于本任务需要的文件、VS Code、BIMBase 和辅助工具操作，不扩展到无关文件，也不代表获得系统未授予的权限。

## 多图处理

- 依据共同路口、线路走向、相邻结构及用户说明判断场景关系。同一场景的不同视角或局部图结合建模，统一尺度、坐标及连接关系；不同场景分别建立模型和交付目录。不能仅因道路样式相似就合并。
- 同一批图片集中问 5 个问题，不对每张图分别问 5 个。场景关系不明确时纳入这组问题。
- 同场景图片出现明显矛盾时，先排除视角和遮挡造成的表象差异，再在 5 个问题中引用图片编号或文件名、指出冲突，请用户指定基准图。不自行以清晰度决定取舍，也不默认生成两套方案。基准图控制冲突部分，其他图片补充不冲突的细节。
- 回答后追加图片引入新的关键矛盾，只补问该矛盾，暂缓依赖它的部分。

## 复原原则

**贴近图片优先。** 保持可辨认的道路走向、曲线、路口轮廓、线路相对位置和比例，不为迁就组件或加快生成而重设计路网。还原透视图表达的空间关系，不能把像素坐标直接当作等比例平面坐标。

**仅建主要交通干线。** 默认还原图片范围内的道路、铁路及必要的路口、桥梁结构，按表达车道需要保留标线、路缘和分隔带。不默认增加绿化、路灯、车辆、建筑、车站建筑或图片外路网。小型支路、辅路是否保留，结合该图在开工问题中明确。

**允许合理推定。** 遮挡、模糊和无尺度部分，依据可见线索、相邻线路及常见道路铁路尺寸估算，保持连续，不仅因普通图像不确定性而留空或追加确认。记录推定项及依据，不称为实测值；推定不能扩大范围或覆盖用户明确给出的尺寸、车道数和层次关系。

## 执行流程

1. **识别与记录。** 放大关键区域，区分可见事实、推定内容和关键矛盾。记录中心线、连接端点、宽度、车道、轨数及上下层关系，制作原图识别标记。多图保留来源对应关系。
2. **集中参数。** 用一个明确的配置文件或入口配置区管理道路宽度、车道数、车道宽度、曲线控制点或半径、铁路高度及线间距等，附中文说明、单位和取值约束。由同一配置推导模型连接、高程及相关布局图，避免手动同步多处数值。原图识别标记保留原图依据，不随模型参数修改伪造识别结果。不把历史项目的双线、6 车道或净空值自动套用到新图。
3. **复用与适配。** 优先选择相关库组件，仅在用户要求时使用全部组件。允许自行修改执行副本或补写新组件，依次考虑参数调整、连接及曲线适配、必要的新组件；不因缺少匹配组件再次例行询问。保留库原文件和采用的原始源码副本，说明直接复用、修改复用与新增代码的来源。
4. **代码与新工程。** 在新版本目录准备源码和入口，在 VS Code 中打开进行本次任务。可通过终端及 SDK 执行，无需模拟逐字输入。BIMBase 新建独立空白工程，确认活动工程路径后生成；入口检查目标场景为空，防止重复叠加。不得因重试清空未知工程或旧版本。
5. **外观检查。** 实际查看 BIMBase 总览，对照图片检查走向、曲线、路口、比例和层次，排除明显缺失、断路、错位及上下层颠倒。总览无法判断或有明显问题时才检查必要局部。优先局部修正，不改变可见布局；必须明显偏离图片且无法合理判断时说明冲突。默认不做完整碰撞检测、逐段净空核算、轨距专项检查或工程规范审查。
6. **保存与交付。** 保存 `.p3d`，核对目标文件存在及软件保存结果，保存真实模型截图。记录实际完成的外观检查和局部修正，不称为无碰撞保证或工程验证。不默认反复重开工程追加深度检查。完成后只提供成果链接，不为展示效果额外切换软件窗口、设置指定视角或打开指定配置文件。

主要编辑方式是修改集中配置后重新生成；不默认要求 BIMBase 内的组件属性可调。交付说明须指出配置入口、生成命令和版本创建步骤。

## 输出与版本

输出根目录优先使用用户指定位置，其次读取 `BIMBASE_OUTPUT_ROOT` 环境变量；均未设置时使用当前项目的 `outputs/bimbase`。先报告解析后的绝对路径。新任务用“任务名称_YYYYMMDD”子目录，取实际执行日期；同名时追加 `_v02`、`_v03` 等，不覆盖已有内容。

同任务改参数再生成，也创建独立的新版本目录和新工程。将所选旧版本的配置、源码复制到新目录后修改，保留各版模型、配置、源码、检查记录与预览，注明来源版本和本次变化。沿用已有 5 问答案，不例行再次确认。只有用户明确要求覆盖旧工程或更换位置时才改变策略。

每版交付原生模型、集中配置与布局、所用源码及生成入口、原图及识别图、实际模型预览和简要说明。检查记录可写入说明，无需另做深度核验报告。最终提供绝对路径链接，注明估算项和实际限制；脚本执行成功不能代替模型保存成功。
