# 迁移与兼容性维护

上游审查日期：2026-06-14

## 重命名

当前规范名称为 `blender-control`。将来重命名时，必须将此名称保留为别名至少一个发布周期，并更新：

- `SKILL.md` 文件头中的名称和描述。
- `skill_lifecycle.yaml`。
- `assets/evals/evals.json`。
- `references/readiness_report.md`。
- 在单独的仓库整体发布步骤中更新技能目录或市场展示信息。

## 弃用

只有新的 Blender 技能覆盖相同主要任务，且触发覆盖率不低于本技能时，才可以弃用。弃用说明必须包括：

- 替代技能名称。
- 兼容期。
- 面向用户的迁移提示。
- 评估证据，证明直接触发、间接触发、负例及相邻技能重叠场景的覆盖没有减少。

## 合并

只有主要任务仍然是一个完整的 Blender 控制工作流时，才可以与相邻技能合并。不得仅为吸收图片生成、Three.js 前端、教学视频或通用文档任务而合并。

合并需要的证据：

- 功能重叠矩阵。
- 合并前后的触发评估结果。
- 更新后的任务交接规则。
- 草稿版本发布检查结果。

## 拆分

某个子领域过于庞大或需要独立工具时，应拆分本技能，例如：

- 专门的 Blender 相机/视频渲染技能。
- 专门的工业参数化建模技能。
- 专门的绑定/动作重定向技能。

拆分需要的证据：

- 新技能各自的职责边界。
- 双方的负面触发用例。
- 旧提示词的迁移说明。
- 拆分后各项产物的阶段检查结果。

## 兼容性

兼容性规则：

- 保留 `blender-control` 对 Blender、BlenderMCP、bpy、产品建模、材质、修改器、相机动画、导出及故障排查任务的触发描述。
- 没有替代路径时，不得新增对某个 MCP 服务器、WebSocket 封装、外部 API 或付费服务的强制依赖。
- 本地汉化版本以简体中文为主要说明语言，保留 Blender API 和工具名称的英文原名。

## 迁移证据

上游初次创建阶段的证据：

- 上游仓库创建该技能时，没有已有的本地 `blender-control` 技能。
- 新技能为增量添加，不修改相邻技能。
- 来源仓库用于参考设计，并非整体复制。
- 完整的自动检查证据记录在 `references/readiness_report.md`。
